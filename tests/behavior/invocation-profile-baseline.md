# 职业战略教练调用与档案默认值：RED 基线

日期：2026-09-19

## 评估边界

这是一份确定性仓库基线，而不是伪造的模型对话记录。本次测试环境不能固定模型版本、会话历史、已启用的 Skills 或客户端设置，因此没有把一次不可复现的自然语言回复冒充为“逐字标准响应”。以下结论只依据当前提交中的 `AGENTS.md`、Skill 元数据及命令行接口；三个提示词均按原文记录。

Codex 当前没有注册任意裸自定义斜杠命令的机制；本项目也尚未声明项目级文本别名。因此 `/ZhiYeJiaoLian` 在此基线中不是原生命令，后续实现只能把它明确标为项目级文本触发约定。

## 场景 1：快捷入口

提示词（逐字）：

```text
/ZhiYeJiaoLian
```

判定标准：

- 项目规则明确把该文本路由到职业战略教练 Skill；
- 明确说明它是项目级文本别名，而不是 Codex 原生斜杠命令；
- 未附带职业问题时，只询问用户本次希望解决的职业问题。

当前受限评估：**FAIL**。`AGENTS.md` 没有 `/ZhiYeJiaoLian`，也没有到 `.agents/skills/career-strategy-coach/SKILL.md` 的路由契约。

## 场景 2：自然语言入口

提示词（逐字）：

```text
帮我分析一下职业路径
```

判定标准：

- 不要求用户先输入别名；
- Skill 的发现元数据或项目规则明确覆盖“分析职业路径”这一触发意图；
- 进入职业教练流程，而不是把个人信息写入 Skill。

当前受限评估：**FAIL**。权威 Skill 不在仓库级 `.agents/skills/` 发现位置，当前项目规则也没有自然语言路由声明。

## 场景 3：未命名的新档案

提示词（逐字）：

```text
为我创建个人职业档案。我还没有起档案名称。
```

判定标准：

- 先要求用户提供一个单层档案文件夹名称；
- 在写盘前提议 `你的skill所在位置\career-profiles\<用户起的名字>` 的绝对路径；
- 写盘前展示且仅展示五个待创建项：`career-profile.md`、`career-strategy.md`、`plans/`、`reviews/`、`decisions/`；
- 等待用户明确确认后才初始化，不把默认路径视作授权；
- `career-profiles/` 不进入 Git。

当前受限评估：**FAIL**。当前 CLI 只有 `init` 和 `validate`，没有只读、确定性的 `propose --root ... --name ...` 接口；项目也没有默认私有档案根目录或忽略规则。

## RED 结论

三个场景都缺少可由仓库文件和自动化测试验证的契约。后续 GREEN 评估必须再次使用以上三个完全相同的提示词，并单独记录每条标准的 PASS/FAIL 与复现限制。
