# 职业战略教练 Skill 设计规格

日期：2026-09-19
状态：待用户审阅
目标：把职业规划资料整理为一套面向通用职场用户、可安装、可验证且不保存个人信息的 Codex Skill。

## 1. 产品定位

职业战略教练不是岗位推荐器，也不是用年龄套结论的职业测评。它帮助用户识别当前位置、盘点职业资产、判断发展阶段、评估职业生态位、比较候选路线、制定行动计划，并根据现实反馈持续复盘。

职业是主系统；财富、健康、家庭、关系和意义作为职业决策的约束与校验维度。最终目标不是取得某个职级，而是把能力逐步转化为成果、方法论、杠杆、资源和可复利资产，从而提高职业自主权与人生选择权。

## 2. 设计依据与优先级

资料冲突时按以下优先级处理：

1. `职业规划教练核心框架摘要.md` 是规范性主框架。
2. 其他文本用于补充诊断条件、工作流、模板和反例。
3. 原始 PDF 用于追溯原模型，不直接覆盖核心摘要已经完成的修正。

保留四个核心思想：生态位、阶段、能力替换、资产化。

必须修正四个原始偏差：年龄刚性、管理导向、职业中心主义、增长中心主义。

## 3. 已确认约束

- 面向通用职场用户，不嵌入任何特定个人的背景。
- 采用 A/C 混合架构：`SKILL.md` 包含完整核心判断与教练流程，脚本只处理确定性的工作区初始化和结构验证。
- 诊断采用“强／中／弱／未知 + 证据 + 置信度”，不生成无依据的 0–100 分。
- Skill 源码保存在 `你的skill所在位置`，并安装到用户批准的 F 盘个人 Skill 目录。
- 安装副本路径为 `你的skill所在位置`；不修改 `CODEX_HOME`，通过明确路径调用。
- 实施采用子代理分任务开发，每个任务依次经过规格符合性审查和代码质量审查。
- 未经用户针对具体操作明确授权，不得在 C 盘创建、修改、复制、安装或缓存本项目的任何内容；测试和临时产物也必须位于 F 盘。
- Skill 安装目录不得保存用户姓名、经历、收入、目标、诊断结果或职业档案路径。
- Skill 不记忆个人档案位置；每个新上下文中由用户明确提供或选择工作区。
- 默认只在对话中分析。任何文件写入前，必须展示解析后的目标目录和拟创建或更新的文件，并获得明确确认。
- 用户档案统一为 Markdown，并保存在用户选择的独立职业工作区。
- 访谈每轮最多提出 3 个高价值问题；已有信息不得重复询问。

## 4. Skill 包结构

```text
career-strategy-coach/
├─ SKILL.md
├─ agents/
│  └─ openai.yaml
├─ scripts/
│  └─ career_workspace.py
└─ assets/
   └─ workspace-template/
      ├─ career-profile.md
      └─ career-strategy.md
```

### 4.1 `SKILL.md`

作为单一知识入口，包含：

- 适用场景和不适用边界。
- 资料层级和核心原则。
- 意图路由。
- 诊断、规划、决策、复盘的完整流程。
- 六阶段、六类职业资产、人生约束、生态位和路线选择规则。
- 证据、未知项和置信度规范。
- 每类输出的最低内容要求。
- 个人信息与工作区隔离规则。
- 何时调用工作区脚本。

不把用户档案、个案数据、默认输出路径或动态状态写入 `SKILL.md`。

### 4.2 `career_workspace.py`

脚本只执行可机械验证的文件操作，不替代职业判断。计划提供两个命令：

```text
init --path <absolute-path>
validate --path <absolute-path>
```

`init`：

- 只接受用户明确选择的绝对路径。
- 创建职业工作区和标准子目录。
- 从无个人信息的模板生成初始 Markdown 文件。
- 默认拒绝覆盖已有文件。
- 输出实际创建、跳过和冲突的路径。

`validate`：

- 检查必要目录和 Markdown 文件是否存在。
- 检查个人工作区与 Skill 安装目录是否发生嵌套或重合。
- 不读取、上传或记录正文中的个人信息。
- 不执行删除、迁移、联网或隐式备份。

### 4.3 模板

模板只包含字段说明与空白结构，不包含示例人物或真实个人信息。

## 5. 个人职业工作区

用户确认后，创建以下结构：

```text
<用户选择的目录>/<用户选择的文件夹名>/
├─ career-profile.md
├─ career-strategy.md
├─ plans/
├─ reviews/
└─ decisions/
```

### `career-profile.md`

保存相对稳定或逐步累积的信息：

- 基础职业事实。
- 重要现实约束。
- 能力、成果、杠杆、资源等证据。
- 六类职业资产状态。
- 当前主阶段及阶段任务完成情况。
- 当前生态位。
- 待验证假设和未知项。

### `career-strategy.md`

保存当前有效的战略版本：

- 人生与职业目标。
- 当前主要矛盾。
- 候选路线及比较。
- 选定路线与理由。
- 核心 Gap 与优先级。
- 3 年假设、1 年里程碑和当前 90 天重点。
- 风险边界、退出条件和 Enough Point。

### 其他目录

- `plans/`：带日期的 90 天、30 天和每周行动计划。
- `reviews/`：带日期的周、月、季度和年度复盘。
- `decisions/`：跳槽、转行、创业、项目选择等单项决策记录。

历史报告使用新文件保存；`career-profile.md` 与 `career-strategy.md` 是当前状态文件。更新当前状态文件前要说明拟修改的章节，避免静默覆盖用户内容。

## 6. 意图路由

Skill 首先识别用户所需模式：

| 模式 | 典型请求 | 行为 |
| --- | --- | --- |
| 快速咨询 | “这个机会值不值得接” | 只执行相关模块，不强制完整访谈 |
| 全面诊断 | “我不知道下一步怎么走” | 分轮收集事实并形成完整画像 |
| 路线比较 | “专家还是管理” | 生成 2–4 条候选路线并比较 |
| 决策分析 | 跳槽、转行、创业、学习投入 | 分析收益、成本、风险和可逆性 |
| 行动规划 | “制定未来 90 天计划” | 把已选战略拆为可观察行动 |
| 复盘调整 | “我执行一个月了” | 对照旧计划，更新证据、Gap 和下一周期 |
| 档案操作 | 创建、保存或更新职业档案 | 先确认绝对路径和文件清单，再写入 |

如果用户只问单一问题，不得以“流程完整”为理由强迫用户完成全套诊断。

## 7. 分析模型

### 7.1 阶段模型

年龄只作为弱参考。实际阶段根据任务完成度和证据判断：

1. 探索与基建：方向、职业社会化、基本技能、完整项目经验。
2. 定位与深耕：主赛道、明确长板、方法论、代表作、专业身份。
3. 跃迁关键：从执行者升级为结果负责人，形成判断、取舍、资源配置和不可替代能力。
4. 蜕变与自主：能够决定做什么、组织复杂结果并提高职业自主权。
5. 生态变现：把品牌、客户、方法、股权、内容和关系转化为可复利资产。
6. 传承与第二曲线：降低对单一职业系统的依赖，形成选择权、传承和非功利事业。

允许多个阶段同时部分成立。输出必须区分：年龄参考、实际主阶段、已完成任务、当前欠账和提前具备的高阶能力。

### 7.2 六类职业资产

- 方向资产。
- 能力资产。
- 成果资产。
- 杠杆资产。
- 资源资产。
- 自由资产。

每项只能评为强、中、弱或未知，并必须列出支持判断的证据。证据不足时使用“未知”，不得把缺少信息等同于能力弱。

### 7.3 人生约束

检查职业选择对财富、健康、家庭、关系和意义的影响。人生账户不是另一套完整人生测评，而是用于识别不可接受的代价、现实边界和当前主要矛盾。

### 7.4 生态位

从四层分析：

- 岗位：杠杆、稀缺性、价值捕获、可替代性。
- 企业：业务核心度、产业链位置、壁垒、成长空间。
- 行业：周期、竞争、技术变化和结构性风险。
- 个人：匹配度、资产复用率、进入成本、迁移能力和生活约束。

输出“当前生态位—目标生态位—迁移成本—预期收益—所需证据”，不使用未经验证的乘法公式制造精确感。

### 7.5 路线与决策

支持专家、管理、产品或业务负责人、创业、独立顾问、超级个体、内容/IP 和资源型路线。每次选择 2–4 条与当前事实相关的路线，比较：

- 能力与性格匹配。
- 现有资产复用。
- 收益与成长空间。
- 时间和机会成本。
- 下行风险与最坏结果承受力。
- 可逆性。
- 对人生账户的影响。
- 需要先验证的关键假设。

资料不足时给出“最值得验证的路线”，不替用户作确定性人生决定。高成本、低可逆选择优先拆成低成本验证实验。

## 8. 证据与置信度

分析必须区分：

- 事实：用户明确提供或档案中已有的内容。
- 证据：项目、结果数据、作品、反馈或可核实记录。
- 推断：由事实推导但尚未验证的判断。
- 未知：缺少足够信息。
- 假设：需要通过行动验证的未来判断。

每个重要结论标记高、中、低或未知置信度，并解释影响置信度的关键证据。不得为了显得完整而补造收入、能力、行业趋势或个人偏好。

## 9. 教练工作流

### 9.1 全面诊断

1. 汇总已有事实，列出真正影响判断的未知项。
2. 每轮最多询问 3 个问题，并说明提问目的。
3. 盘点六类职业资产。
4. 判断主阶段和阶段欠账。
5. 分析当前生态位与人生约束。
6. 明确目标、Enough Point 与不可接受代价。
7. 生成并比较候选路线。
8. 确定关键 Gap 和验证优先级。
9. 输出 3 年假设、1 年里程碑、90 天结果、30 天行动和本周动作。

### 9.2 复盘

复盘只询问计划执行、结果证据和预期偏差。随后更新：

- 已完成行动与实际结果。
- 新增职业资产证据。
- 被证伪或被加强的假设。
- 阶段和生态位判断。
- 下一周期行动。

复盘不得无理由重做完整初始访谈。

## 10. 输出契约

普通分析按以下结构组织：

1. 已知事实。
2. 核心判断与置信度。
3. 判断依据。
4. 主要风险和反方论证。
5. 候选方案及权衡。
6. 推荐的验证路径。
7. 下一步行动。
8. 仍需补充的信息，最多 3 项。

行动计划必须写清：动作、预期产出、验证指标、截止时间、依赖和停止条件。避免“提升能力”“打造个人品牌”等无法验收的表达。

## 11. 文件写入与隐私边界

在任何档案写入前：

1. 用户明确提出保存、更新或创建档案。
2. 用户提供或选择目标目录。
3. Skill 解析为绝对路径并展示。
4. 展示拟创建或更新的文件。
5. 获得明确确认后执行。

禁止：

- 把用户信息写入 Skill 目录、安装目录、模板或测试夹具。
- 在 Skill 内保存最近使用路径或用户映射。
- 未经确认覆盖已有档案。
- 默认同步云端或调用外部服务。
- 把对话中的敏感信息写入日志。

## 12. 异常与边界处理

- 信息不足：保留未知项并继续追问，不强行输出完整诊断。
- 信息冲突：并列冲突事实，说明它如何影响判断，再询问澄清。
- 用户要求确定答案：提供推荐与反方论证，但明确哪些仍是待验证假设。
- 用户要求精确分数：解释资料不足以支持数值精度，使用定性等级和证据。
- 目标目录已存在：脚本列出冲突并停止，不自动覆盖。
- 路径位于 Skill 目录中：拒绝初始化并要求另选目录。
- 当前问题涉及实时岗位市场、法律、医疗或具体投资建议：按对应高时效或高风险要求核实资料，不把职业框架当作专业意见替代品。

## 13. 测试策略

实施前先执行无 Skill 的 RED 基线测试，并记录实际失败。至少覆盖：

1. 34 岁但职业基础欠账明显的用户，检查是否机械判为第三阶段。
2. 高薪转行机会与房贷、子女、父母责任并存，检查是否忽略下行风险。
3. 信息很少但用户要求 0–100 分，检查是否生成伪精确结果。
4. 用户要求保存档案但未给路径，检查是否擅自选择目录。
5. 用户只问一个决策问题，检查是否强迫完成整套访谈。

完成 Skill 后对相同场景执行 GREEN 测试，并验证：

- 每轮不超过 3 个问题。
- 阶段依据任务而非年龄。
- 未知不被判为弱。
- 结论包含证据和置信度。
- 路线包含风险、可逆性和验证实验。
- 无确认不写文件。
- Skill 目录中没有个人信息。

脚本测试使用临时目录，覆盖首次初始化、重复初始化、冲突文件、非法嵌套路径和结构验证。最终运行 Skill 结构校验器，并检查安装副本与工作区源码一致。

## 14. 完成标准

当且仅当以下证据同时存在，V1 才算完成：

- F 盘项目工作区中存在完整 Skill 包。
- Skill 已安装到用户批准的 F 盘个人 Skill 目录。
- 官方结构校验通过。
- 工作区脚本的自动化测试全部通过。
- RED 基线失败和 GREEN 改进均有记录。
- 行为测试覆盖五类关键场景。
- 安装包和源码内容一致。
- Skill 包中不存在任何用户个人档案或个人数据。
- 使用临时用户目录成功创建并验证标准 Markdown 职业工作区。

## 15. 非目标

V1 不包含：

- 招聘职位实时抓取。
- 自动联网搜集个人信息。
- 心理测评或人格诊断。
- 无证据的收入预测。
- 自动云同步。
- 将职业建议包装成法律、医疗或投资结论。
- 为了评分而建立未经验证的复杂权重模型。
